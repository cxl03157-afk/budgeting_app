# /quality-check

コードレビュー・マージ前に実行する品質チェックリスト。
フェーズに応じた項目を確認し、すべてパスしていることを確認してから PR を作成する。

---

## フェーズ1: プロトタイプ（現在）

### セキュリティ
- [ ] `innerHTML` にユーザー入力を直接埋め込んでいないか（XSS）
  - OKな例: `el.textContent = userInput`
  - NGな例: `el.innerHTML = userInput`
- [ ] `onclick` 属性内で文字列連結によりユーザー入力を埋め込んでいないか
  - 例: `onclick="f('${userInput}')"` はNGで、シングルクォートがエスケープされていること

### コード品質
- [ ] `console.log` / `console.error` のデバッグ出力が残っていないか
- [ ] 未使用の変数・関数が残っていないか
- [ ] CLAUDE.md のコミットメッセージ規則（Conventional Commits）に従っているか
- [ ] 作業ブランチで作業しており、main への直接 push になっていないか

### 動作確認
- [ ] `prototype/index.html` をブラウザで直接開いて全画面が表示されるか
- [ ] 収支の登録・編集・削除が正常に動作するか
- [ ] ページリロード後にデータが保持されるか（localStorage）
- [ ] ダークモードの切り替えが動作するか

---

## フェーズ2: 最終版（Vue.js + FastAPI + MySQL）※実装開始時に更新

### フロントエンド
- [ ] `npm run lint` がエラーなし（ESLint）
- [ ] `npm run type-check` がエラーなし（TypeScript）
- [ ] 未使用の import・変数が存在しないか
- [ ] API エラー時にユーザーへ通知されているか（サイレント失敗は禁止）
- [ ] HTTP レスポンスの `!response.ok` チェックが実装されているか

### バックエンド
- [ ] `pytest` が全テストパス
- [ ] 参照系エンドポイントに `readonly=True` トランザクションが設定されているか
- [ ] SQL クエリは SQLAlchemy のパラメータバインドを使用しているか（生SQL禁止）
- [ ] バリデーションエラーは HTTP 400 で返却されているか
- [ ] 新しいエンドポイントが CORS 設定に含まれているか

### データベース
- [ ] マイグレーションファイルが追加・更新されているか
- [ ] 外部キー制約が適切に設定されているか

### セキュリティ
- [ ] 認証情報・APIキーがコードにハードコードされていないか
- [ ] `.gitignore` に `.env` が含まれているか

### インフラ（AWS デプロイ時）
- [ ] RDS がパブリックアクセス不可になっているか
- [ ] セキュリティグループが最小権限になっているか
- [ ] 環境変数が EC2 の Systems Manager Parameter Store 等で管理されているか

---

## 実行方法

このコマンドを実行すると、Claude Code が現在のブランチの変更内容を対象に上記チェックリストを順番に確認し、未対応の項目を報告します。
